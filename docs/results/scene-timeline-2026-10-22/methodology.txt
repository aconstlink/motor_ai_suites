Definitions
Early: release the app and notify it after commit, before execute.
Late: release the app and notify it after execute, before backend render_end/swap.
Late is not a fully serial frame: the app can still overlap render_end/swap.
App preparation spans on_graphics through leave_frame (command submission),
including transformation/variable updates and on_render command recording.
Frame cadence is the interval between successive on_graphics starts.
Each render frame n is matched to preparation/submission of app frame n+1.
Both frames must be within the measured window: 399 pairs/run, 1197/mode.
The next frame was never observed starting before release of the current frame.
Every measured frame had 5000 prepare commands and 5002 execute commands
(5000 expected draws plus state push/pop). No GPU draw counter was used.
Timestamps use steady_clock nanoseconds, with per-producer buffers flushed on exit.
No dropped events. Instrumentation is at phase boundaries, not per object.

The aggregate median frame interval is approximately 39% shorter with early sync.
Absolute timings fluctuate substantially; do not directly compare this session
to older benchmark tables or interpret median sub-phases as exactly additive.
These are CPU wall-clock intervals, not GPU timings or scheduler CPU-running
measurements. Overlapping intervals may include preemption and driver waits.
The swap-to-next-prepare gap is not purely idle time; it includes app completion,
handoff, scheduling and context-management work.

Interpretation
The early handoff really overlaps app work with backend execution in this test.
Execute itself does not become substantially shorter; serial prepare/commit and
the remaining app work still limit frame cadence. On_graphics plus on_render
cost substantially more than on_render command recording alone.
The result supports async overlap for this scene-graph workload, not a universal
speedup prediction for direct-rendering benchmarks or GPU-limited applications.
